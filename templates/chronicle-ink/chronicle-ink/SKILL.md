# Chronicle · Ink (Ink Scroll)

You (the Agent reading this) are the whole film crew. The Skill gives you a staged CLI, a fact engine, a
code-synthesized series theme with an exact beat map, a procedural SFX kit, an ink drawing kit and a
HyperFrames renderer. You write the claims, the shot list with one-line captions, the scene code and the
reviews. Nothing calls an image, voice, music, vision or LLM model; the only cost is your own tokens.

> **Hard rule: text LLM plus tools only.** All writing, research, fact checking, scene code and review
> is done by the text LLM that runs this Skill (for example MiniMax M3.1 flash through SandBase, or
> any other Agent model). You may call tools: web search and fetch, the SandBase data APIs, the
> commands below, FFmpeg. You must **never** call a multimodal generation model: no image, video,
> TTS/voice, music or vision model, and no AI-generated picture or audio files. Every frame is drawn by
> the scene code you write, every sound is synthesised by the engine. Contact sheets are reviewed as
> numbers and frames you render yourself, not by a vision model. A film that used a multimodal model is
> not a chronicle-ink film.
>
> **Opt-in exceptions: music and narration.** Only when the user explicitly asks for it, the theme may
> be replaced by an audio file in `music/` described by `music/track.json`: either an openly licensed
> recording (public domain, CC0, CC BY 3.0/4.0; never NC, ND or SA) or an instrumental generated by a
> SandBase music model (for example `minimax/music/2.6` with `is_instrumental: true`, through the
> `sandbase` CLI or API only). The pictures, captions, SFX and every other rule stay as above; the end
> card then credits the track and no longer says the music was made by code. See
> `references/music-track.md`. Likewise a voice-over may be added: one clip per caption from a SandBase
> speech model, saying exactly the caption (`voice/voice.json`, see `references/voice.md`).

## Style packs

`brief.style` (or `new-project.mjs --style`) picks the look; the engine, facts and checks are the same.

| Style | Look | Pack | Use for |
|---|---|---|---|
| `ink` (default) | Chinese ink scroll, LXGW WenKai, "Ink Theme" | `assets/style-pack.json` | people, landmarks, animals |
| `roman` | parchment atlas, Cinzel, soft D-dorian theme | `assets/styles/roman/` | cities, classical subjects |
| `model` | white city model in a dark studio, history projected as light, globe fly-in, photo cards, "Atlas Theme" | `assets/styles/model/` | city life stories: read [style-model.md](references/style-model.md) |

The method is the public "Vibe knowledge showcase" recipe: **set the spec → cut on the beat → put a sound
on every key action → render segment by segment and fix each one before moving on.**

## Spec (defaults)

| | |
|---|---|
| Length | `seconds` 120, 150 (default) or 180; re-hook every 25–35 s; 4–6 / 5–7 / 6–8 knowledge points |
| Format | 16:9 1920×1080 at 30 fps (default), 9:16 1080×1920 optional |
| Language | `brief.lang` = any BCP-47 tag (default `en`; `zh-CN` first class). One script serves many languages |
| Narration | no voice: one short caption per shot saying what the picture shows, bound to verified claims, keywords highlighted |
| Music | the style's series theme (ink: "Ink Theme", D gong pentatonic, guqin-/xiao-like voices), always 88 BPM with sections intro · verse · build · drop · breakdown · build2 · drop2 · outro; optional `music/track.json` ([music-track.md](references/music-track.md)) |
| Loudness | −14 LUFS integrated, ≤ −1.5 dBTP (two-pass loudnorm) |
| Labels | "AI-generated" badge 0–3 s, end card with the AIGC line, AIGC metadata in the MP4 |

Requires Node 22+, FFmpeg/ffprobe and Chrome (HyperFrames 0.8.30 runs through `npx`; rendering always uses
the CPU path so canvas output is identical everywhere). Run `node scripts/chronicle.mjs doctor`.

## City films (subject `city`, structure `life`)

For the "every city has a life story" use case: a city on Wikidata (coordinates + population) locks as
`city` and uses the life structure: birth (river, founding, name) → growth (the built-up area spreads on
the map) → first height → scars (sack, fire, plague, war) → rebirth → today (same map, then and now) →
echo (optionally the author's own line "me and this city"). Read [narrative-city.md](references/narrative-city.md).

The map is real geography, not a model picture:

1. Write `geo/places.json` in the project (centre and places by Wikidata QID, historic areas as
   approximate radii) and run `node <skill>/scripts/geo.mjs --project <p>`. It reads coordinates from
   Wikidata and rivers, water, coast, rail and today's major roads from OpenStreetMap (keyless public
   reads) into `geo/basemap.json`.
2. Ink style: copy `assets/style/exemplars/city-map.js` into `scenes/` and drive every map shot through its
   params (view, areas, places, roads, year stamp, scar). Scenes read the data as `s.geo` and draw it
   with `s.kit.cityMap()`; every frame then carries "© OpenStreetMap contributors (ODbL)".
3. Historic extents are approximations: `cityMap` always tags them "AI 示意 / AI illustration". Year
   stamps and map labels may only show dates and names that are in claims or in a tier-1 source.
4. Model style: add a `chronology` block (camera, eras, extents, walls, events, landmarks) to
   `geo/places.json`, fetch landmark photographs with `node <skill>/scripts/photos.mjs --project <p>` and
   use the single `city-3d` scene (real buildings and heights in WebGL, one continuous camera path).
   See [style-model.md](references/style-model.md) and the step-by-step
   [city-film-recipe.md](references/city-film-recipe.md) (how the Rome, New York, Barcelona and Istanbul samples were made).

Pages this machine cannot reach (Wikipedia is often blocked): fetch them with your own tool and save the
text as `sources/<n>-<name>.txt` in the project (`source: <url>` on the first line). Every later `all`
reads that folder; file names keep the source ids stable.

## Quick start

```sh
node <skill>/scripts/new-project.mjs --out /abs/films/su-shi --topic "苏轼" --film-lang en
node <skill>/scripts/chronicle.mjs all --project /abs/films/su-shi
```

`all` runs research → facts → script → timeline → music → scenes → render → check → report and **stops
whenever you have to write something** (`status: awaiting_…`). Read `AGENT_TASK.md` in the project, write
the file it asks for, run `all` again. Projects must live outside the Skill folder.

### Shot list fields (`script.json`, schema `chronicle-script/2`)

`bars` (1–4 whole bars of one section, so every cut is on a downbeat) · `size` (wide / medium / close /
detail) · `camera` (hold, push-in, pull-out, pan-left, pan-right, rise, parallax) · `transition` (cut,
ink-bleed, scroll-pan, seal-stamp) · `scene` + `params` · `description` · `motion` · `sfx` (`{ beat, kind,
tier, dur_beats }`) · `kind` + `claims` (+ `hedge`) · `caption.<lang>.text` + `em` (keywords) · `kp` ·
`rehook`. Full shape and rules: `work/script/script.request.json` and [pipeline.md](references/pipeline.md).

## Facts first

1. `research` locks the topic to one Wikidata QID, reads Wikipedia and tier-1 sites (CBDB, Britannica,
   UNESCO, GBIF, museums) directly with keyless public reads. Search anywhere you like, but **a fact only
   enters the film after `facts` cross-checks it**: at least 2 independent publishers agreeing, at least one
   tier 1 → `verified`; one source → `single-source` (hedged captions only, ≤ 2, never in intro or drops);
   conflicts → `disputed` ("one account"). Gossip sites are leads, never evidence.
2. If this machine cannot reach a site, read it with your own fetch tool and save the text verbatim to a
   file whose first line is `source: <url>`; pass it with `--source-file`.
3. Every caption, card, title and end-card line binds claim ids; numbers, dates and names in a line must be
   in its claims; quotes need a verified quote claim. Then you answer entailment honestly from the claim
   texts only. See [factcheck.md](references/factcheck.md).

## Story on the theme

The plan (`work/script/plan.json`) gives the theme's sections in bars (150 s: intro 4 · verse 12 · build 4
· drop 8 · breakdown 8 · build2 4 · drop2 8 · outro 7; 120/180 s repeat or trim sections at bar
boundaries), the re-hook bars and the knowledge-point range. Arrange the story to the sections: hook in the
intro, origins in the verse, the turn in the build, the first high point on the drop, cost in the breakdown,
suspense in build2, the defining moment on drop2, an echo in the outro. Different subjects have different
pacing: [narrative-person.md](references/narrative-person.md), [narrative-landmark.md](references/narrative-landmark.md),
[narrative-animal.md](references/narrative-animal.md).

Captions: CJK ≤ 16 characters per line, other scripts ≤ 9 words / 42 characters per line, ≤ 2 lines, never
broken inside a number or date, RTL laid out right-to-left. A caption must be readable in its shot (CJK
7 chars/s, others 3.3 words/s). The glyph check fails with `glyph_missing` instead of rendering tofu.

## Scenes (the #1 quality risk)

Write `scenes/<name>.js` per scene name: `scene('<name>', function (g, s) { … })`, drawing a full frame for
time `s.t` with Canvas 2D and `s.kit` (paper, brush strokes, washes, ink bleed, mountains, water, boat,
pavilion, scroll, bamboo, moon, inkstone, brush, seal, plum, geese, robed silhouette, text reveal, map route,
timeline, count-up, 2.5D `layer()` parallax, composition `frame()`). Start from
`assets/style/exemplars/`. Rules, enforced by a static scan and at run time: deterministic in `s.t`
(`s.kit.rng(seed)`, never Math.random/Date/timers), no network, no DOM or storage. Time every key action on
its cue (`s.cue('seal', 0)`), so the SFX lands on the frame where it happens. Never draw a realistic face.
Do / don't list: [style-pack.md](references/style-pack.md).

## Director's loop (segment by segment)

```sh
node <skill>/scripts/chronicle.mjs scenes --project <p>             # scan + project
node <skill>/scripts/chronicle.mjs render --project <p> --segment s1 # opening ~11 s first
# look at out/segments/s1/sheet.jpg and keyframes/*.jpg against the do/don't list, fix, repeat
node <skill>/scripts/chronicle.mjs render --project <p> --segment s2 # then s3, s4, s5
node <skill>/scripts/chronicle.mjs all --project <p>                 # final deterministic full render + check + report
```

Segments: s1 intro · s2 verse · s3 build + drop · s4 breakdown + build2 · s5 drop2 + outro (or `--segment
<start>-<end>`). At most **3 review rounds per segment**; record each round in `work/review.json`:

```json
{ "schema": "chronicle-review/1", "segments": [{ "id": "s1", "rounds": [{ "sheet": "out/segments/s1/sheet.jpg",
  "findings": ["title overlaps the moon"], "fixes": ["moon moved right"], "open_blocking": [] }] }] }
```

`check` fails `visual_review` when a segment has no round or still has blocking findings. For unattended
runs `all` renders the whole film directly; the review requirement still shows in the report.

## Output

`out/film.mp4`, `out/captions.vtt`, `out/sheet.jpg`, `out/joins.jpg`, `out/report.json`,
`out/report.en.html`, `out/report.zh-CN.html` (bilingual whatever the film language). `check` measures
LUFS and true peak, cuts and sections on downbeats, and each SFX onset within one frame of its action; it
cannot judge whether the mix sounds good — say that a person still has to listen.

## Limits

- No living-person portraits; maps never show national or provincial borders; the AIGC field set of
  GB 45438 stays `verified: false` until checked against the standard text ([compliance.md](references/compliance.md)).
- Three style packs, one theme each (or an opt-in track). Year cards: omit `count` (a year that
  counts up from 0 reads like a wrong date).
- City maps show no national or provincial borders; the OpenStreetMap layers are clipped to the city.
- Fact lexicons (numbers, dates, hedges) exist for English and
  Chinese; other caption languages use the English rules.
- Reference: [pipeline.md](references/pipeline.md), [music.md](references/music.md),
  [sources-allowlist.md](references/sources-allowlist.md), [third-party-notices.md](references/third-party-notices.md).
